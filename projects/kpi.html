01 / Test Goal

두 팔의 차이를 무엇으로 판단할까?

양팔 로봇의 시험 환경을 구성하고, 두 팔이 같은 움직임을 유지하는지와 Master를 Slave가 얼마나 늦게 따라가는지를 평가했습니다. 화면에서 궤적이 비슷해 보여도 각 팔의 목표 추종, 두 팔 사이의 위치 차이, 시간 지연은 서로 다른 문제였습니다.

저는 결과값을 계산하기 전에 무엇을 비교해야 요구한 성능을 판단할 수 있는지부터 정리했습니다. 작은 오차를 만드는 계산보다, 실제 차이를 남기는 측정 기준이 필요했습니다.

02 / Decision

오차를 작게 만드는 대신, 실제 차이를 남기기

  1. 처음의 비교 방식을 검토

    초기에는 한 팔을 반전하고 두 궤적을 회전·이동시켜 맞추는 방식을 검토했습니다. 하지만 정합 과정에서 평가하려는 운동 차이까지 작아질 수 있었습니다.

  2. 제거할 차이와 남길 차이를 구분

    설치 간격에 해당하는 초기 위치 차이만 제거하고, 이후 두 팔의 상대변위 차이는 그대로 남기는 기준으로 정리했습니다.

  3. 추종 오차를 동기 오차와 분리

    각 팔이 제어기 목표를 잘 따라가는지와 두 팔이 같은 운동을 하는지는 따로 계산했습니다.

BEFORE

궤적을 잘 포개는 비교

회전·이동 정합에 따라 운동 차이도 줄어들 수 있음

AFTER

초기 위치만 제거한 비교

두 팔이 출발한 뒤 서로 얼마나 다르게 움직였는지 확인

03 / Measurement

실제 위치와 통과 시각으로 확인했습니다.

동기 시험은 공통 원궤적을 두 팔에 전달하고 실제 TCP 위치를 기록했습니다. 각 팔의 시작 위치를 뺀 뒤 두 움직임의 차이로 동기 오차를 계산했습니다. 한 팔의 actual과 controller desired 사이 오차는 별도로 확인했습니다.

Master–Slave 시험에서는 Master의 실제 움직임을 읽어 Slave 목표를 만드는 경로와 선행 보상을 다뤘습니다. 명령을 보낸 시각 차이가 실제 로봇의 추종 지연을 대신하지 않도록, 두 팔의 실제 위치 파형에서 대응하는 지점의 시각을 비교했습니다.

  1. 동일한 반복 운동의 위치를 기록

    X·Z축에서 Master와 Slave의 실제 위치 파형을 확인했습니다.

  2. 대응하는 지점의 시간 차를 확대

    같은 동작 구간을 확대해 두 곡선의 대응 peak 사이 시각 차를 비교했습니다.

  3. 축별 결과를 나누어 정리

    X·Z축 지연의 RMSE와 MEAN을 각각 정리하고, 50 ms 기준과 비교했습니다.

시험 환경 구성도 따로 확인했습니다.

D405·D435IF의 USB 포트·허브·케이블·영상 조건을 시험해 수집 구성을 선정했습니다. 카메라 환경 확인과 TCP 기반 KPI 계산은 역할을 구분했습니다.

04 / Results

동기 RMSE 0.615 mm, 지연 RMSE 두 축 모두 50 ms 이내

보고서에서 동기 RMSE는 0.615 mm, 추종 지연 RMSE는 X축 46.675 ms · Z축 47.694 ms로 정리했습니다. 동기 오차와 시간 지연을 나누어 측정하고 각 KPI 기준의 달성을 확인했습니다.

05 / Takeaway

측정 기준부터, 다시 확인할 수 있는 결과까지

ENGINEERING NOTE

이번 과제를 통해 성능 검증은 먼저 ‘무엇이 잘 동작해야 하는가’를 측정 가능한 기준으로 바꾸는 과정이라는 점을 배웠습니다. 두 팔이 각각 목표 궤적을 잘 따라가더라도 서로 같은 움직임을 유지한다고 볼 수는 없었고, 명령을 비슷한 시각에 전송하는 것만으로 실제 추종 지연을 설명하기도 어려웠습니다. 개별 추종 오차, 양팔 동기 오차, Master–Slave 지연을 나누어 보면서, 평가 대상과 비교 기준을 명확히 해야 결과의 의미도 설명할 수 있다는 관점을 얻었습니다.

특히 두 궤적을 포개는 정합 과정에서 평가하려는 운동 차이까지 줄어들 수 있다는 점이 인상적이었습니다. 설치 간격에 해당하는 초기 위치 차이만 제거하고 이후의 실제 상대변위를 비교하는 기준을 선택하며, 전처리의 목적과 제거해도 되는 정보를 스스로 설명할 수 있어야 한다고 느꼈습니다. 어떤 차이를 남기고 어떤 차이를 제거했는지, 계산에 어떤 가정이 들어갔는지를 드러내는 일이 측정의 신뢰성을 만든다는 것을 배웠습니다.

또한 그래프를 직접 살펴보며 평균이나 RMSE 같은 요약 수치와 실제 동작을 함께 읽는 습관의 필요성을 느꼈습니다. 위치 파형과 궤적을 함께 확인하면 어느 축과 구간을 더 점검할지 구체화할 수 있었습니다. 카메라의 연결·영상 조건과 TCP 기반 성능 측정을 구분한 경험 역시, 시험 환경의 안정성과 평가 지표의 타당성을 각각 확인해야 한다는 기준으로 이어졌습니다. 앞으로도 요구 성능에 맞는 측정 방법을 먼저 정하고, 좌표 기준·시간 정보·시험 조건을 함께 정리해 다른 사람도 같은 근거로 결과를 재확인할 수 있도록 검증하겠습니다.
